# 配额闸 · 败例清单（动笔改代码前）

题面：试验中心配额已满，抓取仍开新批次，质控与补采被超额洪水灌满。
本题只盯「配额闸」：列表连详情、队列形态、徽标 vs 已用配额、落点入表、印记校验、争用加锁、整笔失败说人话。

## 一、必须被闸门拦下的败例

| # | 败例 | 现状根因 | 期望 |
|---|------|----------|------|
| 1 | 配额已满仍能开新访视批次 | `visits.create_batch` 只校验状态与在采批次数，无配额校验 | 配额满时拒绝开批，给白话原因 |
| 2 | 配额已满仍能抓取 | `mock_crawl` 无整批预检，逐行调用 `add_visit_row` | 抓取前整批预占，不够即整笔拦截 |
| 3 | 抓取半笔入库（前几行进、后几行败） | `mock_crawl` 每行一个事务，非原子 | 预占 + 插入 + 封存在同一事务，异常整笔回滚 |
| 4 | 并发双抓取都成功、击穿配额 | 读-改-写无写锁，两侧读到同一 used | `BEGIN IMMEDIATE` 串行化，后到者重读后失败 |
| 5 | 钉点被彼此盖掉 / 凭证回刷 | 无唯一凭证键、无指纹链 | `gate_key` 唯一 + 指纹链，重复凭证拒绝回刷 |
| 6 | 配额徽标与已用配额拧花仍放行 | 徽标取 `item_count` 汇总、已用取实时行数，两者漂移不校验 | 两者不一致即拦截并提示重算批次计数 |
| 7 | 印记（指纹）对不齐却照样放行 | 无印记校验 | 读侧重算 HMAC 指纹，链上任一行不齐即拦截、拒绝封存 |
| 8 | 抓取成功但配额闸无落点行 | 无账本表 | 每次预占写 `quota_ledger` 落点并封存 |
| 9 | 整笔入库失败抛裸异常/堆栈，用户看不懂 | 直接抛底层异常 | 白话说明：中心、已用/配额、剩余、本次需多少、已整笔拦截且未写入 |
| 10 | 未选中的乙侧骨架残留在读路径，双开轨 | 两侧都实现后未收边 | 编译齐整后只留选定单边（甲侧），删除乙侧与开关 |

## 二、定边

- 甲侧（选定）：**旁路凭证 + 指纹链**。预占时生成当场键 `gate_key`，写入 `quota_ledger` 落点并附 HMAC 指纹（含前一条指纹成链）；读侧只认本条凭证，键唯一拒回刷，指纹对不齐即驳回。
- 乙侧（评估后删除）：过期档归档 + 读侧改读新旗。骨架编译通过后移除，避免闲置骨架残留。

## 三、验收口径

- 落点必须入表（`quota_ledger`），且落点行可页面对照库表。
- 徽标（计数器汇总）与已用配额（实时行数）一致才放行；拧花即拦。
- 印记对不齐即驳回，不得放行。
- 争用下不得双侧同时成功击穿配额。
- 失败信息白话可读。

## 四、落地结果（收卷）

- 甲侧已落地：`app/services/quota_gate.py`（`_record` / `verify_gate` / `list_ledger` / `quota_matrix`）。
- 乙侧骨架评估后未采用，代码库中无残留（`grep 归档/新旗` 仅命中文档）。
- 写侧接入点：`visits.create_batch`（开批，0 占用落点）、`visits.add_visit_row`（追加，1 行）、`visits.mock_crawl`（抓取，整批预占）。
- 读侧/展示：`sites.list_sites` / `get_site` 带 `quota_used`、`quota_badge`、`badge_matches`、`gates`；`/api/quota-gates`、`/api/quota-gate/<key>`、`/api/quota-matrix`；试验中心、访视批次、访视对账、台参数四页均展配额口径，不另开平行轨。
- 覆盖测试：`tests/test_quota_gate.py`（满配开批/抓取拦截、超额整笔回滚、刚好配额、单行追加闸、落点入表与指纹链、篡改驳回、拒回刷、徽标拧花拦截、并发不双花、列表/详情/矩阵展示、种子徽标对齐）。
